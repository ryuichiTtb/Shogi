# Issue #245 ToBe 設計: 評価エンジンと足切りの再設計

> 本書はフェーズ1 PoC([issue-245-phase1-learned-eval.md](./issue-245-phase1-learned-eval.md))の検証結果を踏まえ、
> **「評価(リーフ採点)」と「足切り(候補の絞り込み)」を ToBe(目標形)へどう変えるか**を定める設計書である。
> ユーザーとの設計対話(2026-06-28)で合意した方針を正本化したもの。実装着手前に rule-8 の M1 レビュー
> (単一 general-purpose agent / Issue #109 観点)を経る。route flag は検証完了まで **OFF 据置**(production 無回帰)。

---

## 0. 一言サマリ(初心者向け)

- **何を変える**: AI の「①局面の採点(評価)」と「②そもそもどの手を考えるか(足切り)」の2つ。
- **なぜ変える**: PoC で分かったこと —
  - 評価は **カードの価値が見えていない**(盤面カードは値 `0` のセンチネル、トラップは手作り式)。
  - 学ぶ信号が **「勝った/負けた」だけ**で薄く、**手の良し悪し**を学べていない。
  - 足切りが **盤面カードを機械的に `0` 採点** → トラップが手札にあると盤面カードが探索から落ちる**盲点**がある。
- **どう変える(収束先)**:
  - **評価 = 「ひとつのものさしの学習脳」**。盤面もカード状態も、学習 NN が一律に採点する(センチネル `0` と手作り式を廃止)。
  - **足切り = 捨てない設計**。初回は全アクション(手 + 全カード)を候補に入れ、**枝刈り(αβ + 浅読み読み直し)が読みで動的に削る**。門前払いしない。
- **変えないもの**: 駒の数え上げ + 探索の骨格(αβ / 静止探索)。総合は学習脳と互角・終盤はむしろ上ゆえ、土台として残す。
- **進め方**: **Stage 1(足切り修正・ML 不要・安い)で実物検証 → Stage 2(学習評価)→ Stage 3(将来・学習 policy)**。各段、新しいものさし(対戦勝率 + カード行動)で測ってから前進。

## 1. AsIs(現状)とその弱点

### 1.1 残す良い部分

- **探索骨格**: `search.ts` の World 経路(`findBestMoveWorld` / `negamaxWorld` / `quiescenceWorld`)= card-aware な αβ + 静止探索 + TT。
- **駒の数え上げ評価**: `evaluate.ts`(material 主役 + 小補正)。**349 試合の信頼測定で学習 NN と総合互角・終盤はむしろ上**。
- → これらは ToBe でも**土台として温存**する。再設計の対象は「カード評価」「学ぶ信号」「足切り」の3点に限定する。

### 1.2 弱点①: 評価のカード理解が弱い

- カード価値の出し方が**バラバラ**(`card-spec-server.ts` の `valueModel` / `getCardValue`):
  - **盤面を変えるカード**(`pawn_return` / `double_pawn` / `piece_return` / `double_move`)= 値 **`0`**。「無価値」でなく「**盤面 eval / 探索が別経路で間接捕捉する**」センチネル。
  - **トラップ**(`check_break` / `no_promote`)= **手作り式**(発動確率 × 効果)。
- material(駒の数え上げ)は **トラップや手札カードの価値を構造的に見られない**(盤に出ないため)。

### 1.3 弱点②: 学ぶ信号が薄い

- 現学習は **outcome ラベル(最終勝敗 z∈{+1,0,−1})のみ**。
- 「勝った対局の手は悪手も含めて全部 +1」になるため**信号がうすくノイズ大**。**手の良し悪し(move quality)を学べない** → 勝敗予測マシンにしかなれない(PoC 結論)。

### 1.4 弱点③: 足切りの盲点

- セレクタ `selectBranchCandidates(actions, M, K, ...)` は**カードを `getCardValue` 降順で上位 K 枚だけ**残す(既定 K=1)。
- 盤面カード = `0`、トラップは下限でも 16〜30 の正値。**手札にトラップがあると、K=1 では盤面カードが全て足切りされ探索に到達しない**。
- → ユーザーの実機での不満(無駄カード使用 / 取りこぼし)に直結しうる**構造的盲点**。

## 2. ToBe 全体像 — 収束先

> **評価 = 盤面 + カード状態を「ひとつのものさし」で一律採点する学習脳。**
> **足切り = しない(門前払いしない)。枝刈りは“読み”が動的・安全に行う。**

### 2.1 探索と学習の役割分担(暗記でなく汎化)

- **探索の役割** = 手順を木でたどる(`カード使用 → 相手応手 → 残カード使用 → …` を展開して読む)。**多枚カードの手順網羅は探索が担う**。
- **学習の役割** = 「探索が到達したどんな局面でも一律に正しく採点できるものさし」を作る。**全手順を暗記するのではなく、特徴のパターンで汎化**する(カード手順は天文学的に多く暗記不能 = 正解リスト方式の弱点回避)。

### 2.2 「捨てない」≠「全部を深く読む」(100^N 回避)

- 「捨てない」= **初回に門前払いしない**(全アクションを候補化)という意味であり、**全枝を同じ深さで最後まで読む(指数爆発)わけではない**。
- 動的・安全な枝刈りで「盲点ゼロ」と「爆発しない」を両立する(§4)。

---

## 3. ToBe ① 評価(リーフ採点)

### 3.1 一本化: ひとつの学習ものさし

- World リーフ評価を、**盤面 + カード状態を入力に取る学習 NN** に一本化する。
  - **センチネル `0`(盤面カード)と手作りトラップ式を廃止**。盤面カードの効果は「指した後の局面を NN が採点」して拾い、トラップ/手札カードの価値は **エンコーダのカード状態特徴**(既存: マナ / 手札 / 山札 / トラップ / マーク, [`encoder.ts`](../../src/lib/shogi/ai/learned/encoder.ts))から NN が直接学ぶ。
- 切替点は既存の集約関数 **`evalLeafWorld`**(`search.ts`、フェーズ1 で集約済)1 箇所のみ。スケールは cp 較正(既存の futility / delta margin が cp 前提)。

### 3.2 学ぶ信号を濃く(search-score bootstrapping)

- outcome ラベルに加え、**「その局面を先読みした評価値」も教材化**する。
  - 既存 World 探索(#235)を**採点係**として使い、各局面/各手に**読み抜いた点数**を付与 → NN の学習ターゲットにする。
  - 静止探索 + 詰み(確定値)が混じることで、**一目の評価より正確な教師**になる(循環でなく補正)。
- これにより「勝った対局の悪手」も正しく低評価でき、**手の良し悪しを学べる**。

### 3.3 強さの測り方を変える(評価基準の見直し)

> **勝敗予測の正解率では測らない。** 強さの本質は「各局面・各カード状況で良い手を選べるか」。

- **主**: **AI 同士の直接対戦の勝率**(学習脳 AI vs 安定版 AI、多数局)= 代用品ゼロの強さ指標。
- **主**: **カード行動チェック**(無駄カード = 過剰ドロー / タダ取られ歩打ち / 駒戻し が減るか)= 本来の目的の直接検証。
- 補: 良手一致率 / 悪手回避率。
- ※ outcome 正解率・val MSE は学習の健全性モニタとしては残すが、**強くなったかの最終判定には使わない**(小サンプル錯覚の罠 = 2回の教訓)。

## 4. ToBe ② 足切り(セレクタ)— 捨てない設計

### 4.1 原則

- **初回は全アクション(手 + 全カード)を候補に入れる**。ハードな上位 K-cap(`getCardValue` での門前払い)を**廃止**。
- **盲点(盤面カードが `0` で落ちる)を構造的に消す**。

### 4.2 動的・安全な枝刈り

| 仕組み | 役割 | 安全性 |
|---|---|---|
| **αβ 枝刈り** | 「もう十分ダメ」と分かった枝の続きを読まない | **完全安全**(総当たりと同じ答え。誤って捨てない) |
| **soft reductions** | 見込みの薄い枝は**浅く**読む。浅読みで驚いたら**深く読み直す** | **永久には捨てない**(後から拾える) |

- ガラクタかどうかは**読みが判定**する(人が事前に間引かない)。全選択肢に**最低 1 回は目を通す**(盲点ゼロ)。

### 4.3 `getCardValue` の役割変更

- 門前払いの**足切りには使わない**。残すのは **順序付け**(どの手・カードを先に読むか = αβ を効かせる当て推量)としての用途のみ。
- 順序付け用ヒューリスティックも、**一クラスを機械的に `0` にしない**よう「使った直後の浅い評価」など全アクション同一スケールに是正する(または将来 §5 Stage 3 の学習 policy へ)。

### 4.4 多枚カードの扱い

- 探索が `カード A 使用(1手目) → 相手応手(2手目) → 残カード B 使用(3手目) → …` を**木で展開**し、各到達局面を §3 の学習ものさしで採点する。**手順網羅は探索、採点は学習**(§2.1)。

## 5. 段階計画

> 安く試して、新しいものさし(対戦勝率 + カード行動)で測ってから前進する。route flag は検証完了まで OFF。

### Stage 1 — 足切り廃止(ML 不要・安い・先行)

- **内容**: §4 を World 経路に実装。ハード K-cap 廃止 + soft reductions + 順序付け是正。**学習 NN は使わない**(現 `evaluate` のまま)。
- **狙い**: 学習という大投資の**前に**、「足切りを直すだけでカード挙動が改善するか」を最小コストで実証。元の不満(カード乱用 / 取りこぼし)に**学習なしで効く可能性**を確認。
- **検証**: bench(depthCompleted の棋力ゲート = 退化幅) + カード行動チェック + AI 同士の対戦勝率。深さ低下(カード展開増)が許容内か必ず測る。
- **無回帰**: route OFF 据置(World 経路 dormant)。production(bolt-on)不変。

### Stage 2 — 学習評価へ差し替え(ML)

- **内容**: §3 を実装。World リーフを「濃い信号(search-score bootstrapping)で鍛えた学習 NN」に差し替え(`evalLeafWorld` 集約点 + `useLearnedEval` 二重 flag)。
- **検証**: 対戦勝率 + カード行動 + 速度 bench。Stage 1 比で**強くなったか**を測る。
- **無回帰**: 両 flag OFF = production 完全不変。

### Stage 3 — 学習 policy で順序付け(将来・重い)

- **内容**: 「どの手・カードを考える価値があるか」を NN が直接学習(AlphaZero 流 policy)し、順序付け/reductions を駆動。
- **ゲート**: 計算量が重く GPU 投資判断を要する。Stage 1/2 の結果を見てから着手可否を決める。

### 各段共通

- 着手前に rule-8 M1(計画レビュー)、完了時 M2、本番 cutover 前 M3(いずれも単一 general-purpose agent / #109)。
- 検証は**新しいものさし**で。小サンプル・手作り係数で「良くなった」と早合点しない。

---

## 6. 成功条件 / 非ゲート

- **production 無回帰**: route flag OFF / `useLearnedEval` OFF の二重ゲートで bolt-on 挙動バイト不変。
- **棋力ゲート(各段)**: depthCompleted の退化が許容幅内 + 安定版 AI に対する対戦勝率 ≥ baseline。
- **カード行動**: 無駄カード(過剰ドロー / タダ取られ歩打ち / 駒戻し)が**実測で減る**。
- **盲点解消**: 盤面カードが「手札にトラップがあると探索から落ちる」状態が解消される。

---

## 7. リスク / 留意(#109 観点)

- **深さ低下**: カードを全展開すると枝が増え読みが浅くなりうる → soft reductions + bench 測定で管理。「盲点解消」と「深さ維持」のトレードオフを数値で確認。
- **早合点の罠**: outcome 正解率 / val MSE / 小サンプル / 手作り係数で強さを判定しない(2回だまされた教訓 = #235 gap=0 / 保留 5 試合錯覚)。
- **学習が手作りを超える保証はない**: 現状は互角。ToBe は「試す価値のある方向」であり、各段で実物検証してから前進する。
- **スキュー防止**: encoder / forward は学習と推論で単一実装を共有(フェーズ1 で確立済)を維持。

## 8. AsIs → ToBe 対応表

| 弱点(AsIs) | 直し方(ToBe) | 段階 |
|---|---|---|
| 盤面カード = `0` センチネル / トラップ手作り式 | 盤面 + カード状態をひとつの学習 NN で一律採点 | Stage 2 |
| 学ぶ信号が outcome のみ(手の良し悪し不可) | search-score bootstrapping で先読み評価値も教材化 | Stage 2 |
| 足切りが盤面カードを `0` で門前払い(盲点) | ハード K-cap 廃止 + αβ + soft reductions(捨てない) | Stage 1 |
| 強さを勝敗予測で測っていた | AI 同士の対戦勝率 + カード行動チェックで測る | Stage 1〜 |
| `getCardValue` を足切りに使用 | 順序付け専用に降格(同一スケール是正)/ 将来は学習 policy | Stage 1 / 3 |
